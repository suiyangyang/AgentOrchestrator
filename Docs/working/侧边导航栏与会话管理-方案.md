## 1. 背景与目标

### 1.1 背景

当前 `MainWindow` 只承载一个 `ChatWorkspaceControl`,**没有左侧导航**。在引入多个 Agent、项目、对话之后,用户无法:

- 快速切换不同的对话上下文
- 按"项目"对一组对话进行归类与隔离
- 在不打开对话的情况下预览/管理会话列表
- 跨应用重启之后找回历史对话
- 通过关键字快速定位到某个历史会话

### 1.2 目标(v1)

1. 在聊天区域左侧加入固定宽度的导航栏(参考图片 1)
2. 用"项目 / 对话"二级树把会话分组,支持展开/折叠(参考图片 2 / 图片 3)
3. 点击任意会话可在右侧聊天区加载其聊天内容(从 Agent 拉取,**不存本地**)
4. 点击「新对话」进入空白页,**第一次发送消息**时才真正创建 Session
5. Session 元数据本地持久化到 `./Datas/OrchestratorDb.db`(SQLite)
6. Session 创建时,除了本地落库,还要**通过接口**调用 Agent 侧完成创建
7. 整个数据流遵循**依赖倒置**:UI 层只依赖接口,不依赖 OpenCode / 任何具体 Agent 实现
8. 顶部"搜索"输入框实时过滤导航树,**仅匹配 session.Title**

### 1.3 显式不做(v1)

- 不做消息本地缓存 / 历史消息分页 / 增量同步(全部走 Agent 接口)
- 不做跨设备同步 / 多用户 / 协作
- 不做会话重命名 / 标签 / 收藏 / 项目合并 / 拖拽改归属
- 不做项目多级嵌套(项目只一级,项目下挂对话,顶层"对话"下挂无项目对话)
- 不做 Agent 配置 UI(只接入 `ISessionService`、`IProjectService`、`IMessageService` 这类已有契约)
- 不做会话分享 / Fork / Revert
- 不做自动滚动到底部之外的虚拟化优化
- 不做按消息内容 / 时间 / 项目过滤;搜索**只匹配 session.Title**(子串,不区分大小写)

## 2. 用户故事 & 交互流程

### US-1 顶部固定入口

| 入口 | v1 行为 |
|---|---|
| 新对话 | 右侧聊天区切换到一个**新的空白页**;**未发送消息前不会创建 Session**,也不会写库 |
| 搜索 | 文本框,输入时实时过滤导航树;**仅匹配 session.Title**(子串、大小写不敏感);清空后恢复完整树(详见 §6.5) |
| 任务编排 | 点击后切换到一个**任务编排占位工作页**;该页先提供固定占位内容和后续入口,不与会话树联动 |
| 项目(分类头) | 可展开/折叠;展示"项目列表" |
| 对话(分类头) | 可展开/折叠;展示"无项目归属的对话列表" |

> 展开/折叠样式:完全模仿图片 2 / 图片 3 的箭头切换、`...(更多)` 与 `✎(重命名)` 操作图标、折叠时仅保留标题一行、展开时子项缩进。

### US-2 项目层级

- **项目即一个本地工作目录**(`Project.Directory`),**同时也是 Agent 的工作目录**(详见 §4、§5)
- 一个项目下挂 0..N 个对话
- 项目下没有对话时,显示**「暂无对话」占位文字**,占位**不可点击**、不参与选中态
- 鼠标悬停项目标题,显示 `...`(更多)与 `✎`(重命名/删除等)操作图标(参照图片 2 / 图片 3)

### US-3 对话层级

- "对话"分类头下的对话:**不属于任何项目**的 session,或者叫"自由对话"
- 同样支持展开/折叠;空时显示「暂无对话」占位
- 每个对话项展示:**Title** + **相对时间**(如 `23 小时` / `1 天`)
- 对话列表按 `created_at DESC` 排序,最新会话排在最前
- **Title 默认与 Agent 侧保持一致**:Agent 在创建会话或首次消息后通常会生成/调整 Title,本地库会同步刷新(详见 §6.3);Agent 若没有 Title 字段则保留本地值
- 鼠标悬停对话项,展示选中态高亮(背景变浅灰,如图 2 中的 `LabChromSolution` 选中态)

### US-4 点击会话 → 加载聊天内容

1. 右侧聊天区清空当前 `Messages` 集合,显示 loading 占位
2. 通过 **`IAgentGateway.GetMessagesAsync(agentSessionId)`** 从 Agent 拉取消息历史
3. 拉取完成后,逐条还原成 `ChatMessageViewModel` 并填充 `Messages`
4. 同时异步拉一次 Agent 最新 Title,与本地 Title 对齐(若不同则覆盖)
5. 拉取失败 → 在聊天区显示错误提示,不清空历史(避免误清空)

### US-5 点击「新对话」→ 空白页

1. 右侧聊天区 `Messages` 清空,输入框聚焦
2. **不写库、不调 Agent**;`DraftText` 仍归当前 ViewModel 管理
3. 顶部导航栏**无任何会话项被选中**

### US-6 空白页发送第一条消息 → 真正创建 Session

1. 用户在空白页点击发送(或者 `Enter`)
2. ViewModel 检测 `CurrentSessionId == null && Messages.Count == 0`(条件:确实是空白页)
3. 走"创建 Session"流程(详见 §6.3)
4. 创建成功后,把这条消息作为 session 的第一条消息发出去(走 `IAgentGateway.SendMessageAsync`)
5. 把刚创建的 session **插入到导航树**(根据 WorkingDirectory 解析到对应项目,或归类到"对话"分类头)

### US-7 启动时加载导航树

1. App 启动后,**异步**从本地 SQLite 读取 `projects` 与 `sessions` 表
2. 填充 `SidebarViewModel` 的两个集合
3. 启动时 **SearchText 为空**,显示完整树
4. 如果上次退出时有打开的会话,自动恢复其选中态(v1 可简化为每次启动都是空白页)

### US-8 搜索过滤

1. 用户在顶部"搜索"输入框输入关键字
2. `SidebarViewModel.SearchText` 更新,触发过滤(防抖,详见 §6.5)
3. 导航树收缩为:仅显示标题命中的 session 及其所属项目
4. 自动展开所有命中节点
5. 清空输入框,恢复完整树

### US-9 点击任务编排 → 切换到占位工作页

1. 用户点击侧边栏「任务编排」
2. `MainWindowViewModel` 将当前工作区切换为 `TaskGraphWorkspaceViewModel`
3. 右侧内容区显示 `TaskGraphWorkspaceControl`
4. 若 TaskGraph 功能尚未实现完成,先展示固定占位页,至少包含标题、说明文案和后续操作入口
5. 再次点击会话或「新对话」时,右侧可切回聊天工作区

## 4. 数据模型

### 4.1 持久化范围

**只持久化元数据,绝不持久化消息内容**。具体地:

- 持久化:**项目**(`projects`)+ **会话引用**(`sessions` 元数据)
- 不持久化:消息文本、思考块、工具调用、附件内容、任何聊天区出现的富文本

### 4.2 SQLite Schema(v1)

```sql
-- 项目表:本地工作目录,同时也是 Agent 的工作目录
CREATE TABLE projects (
    id          TEXT PRIMARY KEY,        -- UUID
    name        TEXT NOT NULL,           -- 显示名(默认 = Directory 的最后一段)
    directory   TEXT NOT NULL UNIQUE,    -- 工作目录绝对路径;作为 Agent 的工作目录传入
    created_at  INTEGER NOT NULL         -- unix ms
);

-- 会话表:指向 Agent 侧 session 的引用 + 本地归类信息
CREATE TABLE sessions (
    session_id        TEXT PRIMARY KEY,  -- 本地 UUID
    agent_session_id  TEXT NOT NULL,     -- Agent 侧 session id
    title             TEXT NOT NULL,     -- 会话标题,与 Agent 侧 Title 保持一致
    project_id        TEXT,              -- 所属项目;NULL 表示"无项目",归到顶层"对话"
    created_at        INTEGER NOT NULL,
    FOREIGN KEY (project_id) REFERENCES projects(id) ON DELETE SET NULL
);

CREATE INDEX ix_sessions_project   ON sessions(project_id);
CREATE INDEX ix_sessions_title     ON sessions(title);   -- 用于搜索过滤
CREATE INDEX ix_sessions_created   ON sessions(created_at DESC);
```

> 关于 `title`:
> - **本地 Title 与 Agent Title 保持一致(不强制)**:Agent 若有 Title 字段(如 OpenCode Session.Title),我们尽量与之对齐;Agent 没有 Title 字段则保留本地值
> - 本地默认占位标题固定为「新对话」
> - 同步时机:创建 session 后用 Agent 返回的 Title 覆盖本地;切换/刷新会话时再异步拉一次 Agent 最新 Title 兜底
> - 搜索索引(`ix_sessions_title`)就是为 US-8 服务的

### 4.3 实体关系

```text
Project (1) ────── (0..N) Session
   │
   └── Directory ──── Agent(以 Directory 作为工作目录)
Session (1) ────── (1)   AgentSession (远端,跨进程,只持有 agentSessionId)
```

### 5.2 依赖倒置 — 关键接口契约

> **本节是接口契约(Signature),不是实现。下游实现的细节一律延后到各 Agent 接入阶段。**

#### `IAgentGateway`(新,核心抽象)

```csharp
public interface IAgentGateway
{
    /// 当前后端类型(opencode / 其他),用于诊断与持久化标记。
    string AgentKind { get; }

    /// 在指定工作目录下创建一个新的远端 session。
    /// workingDirectory 对应 Project.Directory,同时作为 Agent 的工作目录传入。
    /// 返回 Agent 侧 session id(后续所有调用都基于它)。
    Task<string> CreateSessionAsync(
        SessionCreateRequest request,
        CancellationToken ct = default);

    /// 列出 Agent 上的会话(用于启动时与本地库对账;v1 可选)。
    Task<IReadOnlyList<RemoteSessionInfo>> ListSessionsAsync(
        CancellationToken ct = default);

    /// 删除 Agent 上的 session。
    Task DeleteSessionAsync(
        string agentSessionId,
        CancellationToken ct = default);

    /// 拉取消息历史(用于点开会话时回填聊天区)。
    Task<IReadOnlyList<RemoteMessage>> GetMessagesAsync(
        string agentSessionId,
        CancellationToken ct = default);

    /// 获取 Agent 侧最新 Title,用于与本地 Title 对齐。
    /// Agent 若没有 Title 字段,实现可抛 NotSupportedException,调用方回退到本地 Title。
    Task<string> GetSessionTitleAsync(
        string agentSessionId,
        CancellationToken ct = default);

    /// 向已存在的 session 发送一条消息(流式响应,沿用现有 IChatStreamChunk 抽象)。
    IAsyncEnumerable<IChatStreamChunk> SendMessageAsync(
        string agentSessionId,
        ChatRequest request,
        CancellationToken ct = default);
}

public sealed record SessionCreateRequest(
    string WorkingDirectory,    // Project.Directory,作为 Agent 的工作目录
    string? Title               // 可选的首选 Title;Agent 可能返回不同的 Title
);

public sealed record RemoteSessionInfo(
    string AgentSessionId,
    string Title,
    long CreatedAt,
    long UpdatedAt
);
```

> **与现有 `OpenCode.Client.ISessionService` 的关系**:`IAgentGateway` 是更高一层的抽象(屏蔽多 Agent 差异)。具体到 OpenCode 时,它的实现内部把 `WorkingDirectory` 透传给 `OpenCodeClient.Sessions.CreateAsync(..., directory: workingDirectory)`。**当前阶段只写接口,不写 OpenCode 实现**。

## 6. 关键流程

### 6.1 启动时加载导航树

```text
App.OnFrameworkInitializationCompleted
  └─> MainWindowViewModel ctor
        └─> SidebarViewModel ctor
              ├─> ISidebarRepository.InitializeAsync   // 建表
              ├─> ListProjectsAsync / ListSessionsAsync
              └─> 填充 Projects / Sessions 集合(SearchText 为空,显示完整树)
```

### 6.2 点击任务编排 → 切换工作区

```text
SidebarViewModel.OpenTaskGraph()
  ├─> MainWindowViewModel.ActiveWorkspace = TaskGraphWorkspaceViewModel
  ├─> TaskGraphWorkspaceViewModel.EnsurePlaceholderInitialized()
  └─> 右侧显示任务编排占位页
```

### 6.3 点击会话 → 加载聊天内容

```text
SidebarViewModel.SelectSession(sessionId)
  ├─> MainWindowViewModel.ActiveWorkspace = ChatWorkspaceViewModel
  ├─> ChatWorkspaceVM.CurrentSessionId = sessionId
  ├─> ChatWorkspaceVM.Messages.Clear()
  ├─> 调 IAgentGateway.GetMessagesAsync(agentSessionId)
  │     └─> 把 RemoteMessage 还原成 ChatMessageViewModel
  ├─> (并行)调 IAgentGateway.GetSessionTitleAsync(agentSessionId)
  │     └─> 若返回的 Title ≠ 本地 Title,则 UpdateSessionAsync + 刷新侧栏显示
  └─> 滚动到底部
```

### 6.4 空白页首次发送 → 创建 Session

```text
ChatWorkspaceVM.Send()
  ├─ 检测:CurrentSessionId == null && Messages.Count == 0
  ├─ 决定 WorkingDirectory:
  │   ├─ SidebarViewModel 有 "当前项目" 选中态 → Project.Directory
  │   └─ 否则 WorkingDirectory = AppContext.BaseDirectory
  ├─ 解析 projectId:
  │   ├─ 找 Project.Directory == WorkingDirectory 的本地项目
  │   └─ 若没有,自动 CreateProjectAsync(name = Path.GetFileName(WorkingDirectory.TrimEnd('/','\\')), directory = 路径)
  ├─ 本地:
  │   1) 生成 SessionRecord(sessionId = Guid)
  │   2) 初始 Title = "新对话"
  │   3) ISidebarRepository.CreateSessionAsync(record)
  ├─ 远端:
  │   4) IAgentGateway.CreateSessionAsync(SessionCreateRequest(WorkingDirectory, Title))
  │      -> 返回 agentSessionId
  │   5) 回写 record.AgentSessionId,UpdateSessionAsync
  ├─ 发送:
  │   6) 把这条消息 append 到 Messages(User 角色)
  │   7) IAgentGateway.SendMessageAsync(agentSessionId, ChatRequest)
  │      -> 流式响应,append Assistant 消息
  ├─ Title 同步:
  │   8) 流结束后(或中途 Agent 上报 Title 变化),调用 GetSessionTitleAsync
  │   9) 用 Agent 的 Title 覆盖本地 Title,UpdateSessionAsync
  │   10) SidebarViewModel 刷新该节点显示
  └─ 收尾:导航树新增该 session
```

### 6.5 失败处理

| 场景 | 行为 |
|---|---|
| 本地创建成功 + 远端失败 | **回滚本地**,删除刚创建的 SessionRecord,聊天区显示"创建会话失败"提示 |
| 远端成功 + 本地写库失败 | **回滚远端**(调 `DeleteSessionAsync`),提示用户重试 |
| `GetMessagesAsync` 失败 | 聊天区显示错误,**不清空**;用户可手动刷新 |
| `SendMessageAsync` 流中断 | 当前消息保留 `IsStreaming=true`,显示重试按钮(后续迭代) |
| `GetSessionTitleAsync` 失败 / Agent 不支持 | **静默回退**,继续使用本地 Title;不打扰用户 |

### 6.6 搜索流程

```text
SidebarViewModel.SearchText 变更
  ├─> 防抖 200ms(避免每键击都触发 SQLite 查询)
  ├─> 空文本:
  │     - 清空过滤集合,显示完整 Projects / Sessions 树
  └─> 非空文本:
        - ISidebarRepository.SearchSessionsByTitleAsync(SearchText)
          (LIKE '%kw%' COLLATE NOCASE)
        - 拿到命中 SessionRecord 列表
        - 构造临时视图:
            Projects:仅保留至少有一个命中 session 的 Project
            顶层"对话":仅当存在 projectId IS NULL 的命中 session 时显示
        - 自动展开所有命中的项目节点
```

## 9. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| OpenCode 接口与本地模型字段语义不一致 | 中 | 在 `IAgentGateway` 上做映射,不直接暴露 OpenCode DTO 到 ViewModel |
| SQLite 文件被占用(Windows 进程占用) | 低 | 打开时 `journal_mode=WAL`,关闭句柄放在 finally |
| 启动时 SQLite 加载阻塞 UI | 中 | 加载放后台 `Task.Run`,UI 先显示骨架,完成后回填 |
| 创建 session 时网络抖动导致远端成功本地失败 | 中 | §6.4 已设计为"本地+远端"原子事务风格;失败一侧必须回滚另一侧 |
| 大量历史 session 导致列表卡顿 | 低(v1) | 列表用虚拟化或限制取最近 100 条;Title 已建索引 |
| Agent 接口未来变更(OpenCode 升级) | 中 | 接口只暴露稳定子集,变更被吸收在 `OpenCodeAgentGateway` 内部 |
| Title 同步延迟或不一致 | 低 | 切换会话时拉一次 Agent 最新 Title 兜底;Agent 不支持时静默回退本地值 |
| Project 与 Agent 工作目录权限不一致 | 中 | 创建 Project 时校验目录存在且可读;不可读则创建失败并提示 |
