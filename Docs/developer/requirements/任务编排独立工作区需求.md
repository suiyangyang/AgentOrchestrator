# 任务编排独立工作区需求

## 1. 目标

为任务编排提供一个独立于聊天主工作流的工作区，用于统一管理：

- `TaskGraph`：真实生成、真实执行、带运行状态的任务图实体
- `Template`：用于辅助生成 `TaskGraph` 的模板资产

该工作区需要解决以下问题：

- 当前左侧主导航中的“任务编排”与“项目 / 对话”语义混杂
- Chat 底部的“编排选项”混合了普通对话、自动生成、固定模板三类不同能力
- 用户缺少一个统一入口来管理模板、查看运行中的任务图、复用既有任务图

## 2. 领域定义

### 2.1 TaskGraph

`TaskGraph` 是执行实体，具有以下特征：

- 可被创建、保存、打开、执行、暂停、继续、取消
- 带有节点、边、执行状态、检查点、运行输出等执行期数据
- 是一次具体运行实例，而不是模板蓝图

### 2.2 Template

`Template` 是生成资产，具有以下特征：

- 不直接执行
- 用于辅助生成新的 `TaskGraph`
- 可表达图骨架、节点约束、推荐流程、生成提示和适用场景
- 用户选择模板后，系统需要结合当前输入生成本次使用的 `TaskGraph`

### 2.3 关系

`Template` 与 `TaskGraph` 是两类不同对象，关系如下：

`Template` + 用户输入 + 当前上下文 -> 生成 `TaskGraph` -> 执行

`Template` 不是“可直接运行的 TaskGraph”，`TaskGraph` 也不是“顺手保存的模板”。

## 3. 一级入口

任务编排需要从聊天主页面左侧导航中抽离，改为全局入口。

### 3.1 入口位置

- 在标题栏提供“任务编排”入口按钮
- 点击后，主界面切换到独立的任务编排工作区
- 不使用“小型弹窗承载完整任务编排功能”的方案

### 3.2 与聊天的关系

- 聊天页仍然保留“普通对话 / 自动编排 / 使用模板”这类轻量入口
- 深度管理 `TaskGraph` / `Template` 时，进入独立任务编排工作区
- 聊天是对话主工作流，任务编排工作区是编排资产管理与执行主工作流

## 4. 页面结构

任务编排工作区采用与当前主页面一致的基础结构：

- 左侧：导航区
- 右侧：内容区

这里的“一致”仅指视觉与交互骨架一致，不表示复用“项目 / 对话”那套业务结构。

## 5. 左侧导航区

左侧导航区采用“顶部快速动作 + 可折叠分组列表”的模式。

### 5.1 顶部快速动作

顶部固定提供两个入口：

- `新任务图`
- `搜索`

说明：

- `新任务图`：创建新的 `TaskGraph`
- `搜索`：统一搜索 `Template` 与 `TaskGraph`

### 5.2 分组结构

左侧包含两个可展开/收缩的分组：

- `模板`
- `任务图`

分组标题需要支持展开/收缩交互，视觉和主页面 section header 保持一致。

### 5.3 模板分组

`模板` 分组展示用户可用的模板资产，例如：

- 模板 1
- 模板 2

模板行要求：

- 点击行：在右侧打开模板详情/编辑视图
- Hover 行：显示 `...` 操作入口

模板行 `...` 的首批操作包括：

- 重命名
- 复制
- 删除

`模板` 分组标题需要提供 `+` 操作，用于创建新模板。

### 5.4 任务图分组

`任务图` 分组展示真实的 `TaskGraph` 实例。

每个任务图行至少显示：

- 任务图名称
- 执行状态
- 所属项目（若存在）

执行状态包括但不限于：

- 草稿 / 未运行
- 执行中
- 等待确认
- 已完成
- 失败
- 已取消

所属项目显示规则：

- 有所属项目：显示在任务图名称下方第二行
- 无所属项目：不显示第二行，不显示“无项目”字样

任务图行要求：

- 点击行：在右侧打开该 `TaskGraph`
- Hover 行：显示 `...` 操作入口

任务图行 `...` 的首批操作包括：

- 删除
- 重命名
- 修改所属项目

“所属项目”在本阶段定义为**管理归属信息**，主要用于导航组织和筛选，不直接等同于执行目录。

## 6. 右侧内容区

右侧内容区根据左侧所选对象切换：

### 6.1 选中 Template

右侧显示模板详情/编辑内容，至少包含：

- 模板名称
- 模板说明
- 模板结构预览
- 基于当前模板生成 `TaskGraph` 的入口

### 6.2 选中 TaskGraph

右侧显示真实任务图内容，至少包含：

- 图结构
- 节点详情
- 执行状态
- 执行控制
- 运行输出 / 检查点信息

## 7. Chat 侧入口调整

Chat 输入区的“编排模式”需要与独立工作区的领域定义保持一致。

Chat 侧的目标模式为：

- `普通对话`
- `自动编排`
- `使用模板`

其中：

- `普通对话`：直接按普通 OpenCode 对话发送
- `自动编排`：根据用户输入自动生成 `TaskGraph`
- `使用模板`：由用户选择 `Template`，再结合当前输入生成 `TaskGraph`

Chat 侧不再把固定内置模板直接暴露为顶层并列模式。

## 8. 内置模板定位

当前系统中的内置能力，例如：

- 任务列表
- 功能开发
- Bug 列表 / 缺陷处理

后续统一归入 `Template` 体系，不再作为“Chat 顶层编排模式”长期保留。

它们的产品定位应为：

- 官方模板
- 可被用户选择并实例化为 `TaskGraph`

## 9. 首批交互要求

首批版本需要满足以下体验要求：

1. 用户可通过标题栏进入独立任务编排工作区
2. 左侧可在 `模板` 与 `任务图` 两类资产之间切换
3. 左侧行项目支持 hover 操作菜单
4. 任务图列表支持状态可视化
5. 模板与任务图都可在右侧打开并查看
6. Chat 中的“使用模板”可以与模板资产打通

## 10. 暂不纳入本阶段

以下内容不属于本阶段必做范围：

- 多窗口并行管理任务编排
- 在独立任务编排页中复刻聊天左侧“项目 / 对话”树
- 将“无项目”显式显示为列表文案
- 把 `Template` 直接当作可执行 `TaskGraph`
